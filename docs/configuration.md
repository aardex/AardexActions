# Configuration and secrets boundary

Inputs are declared by each component's `action.yml`; consumers supply values through their own workflows and GitHub secrets/environment configuration. This repository contains no deployable environment settings, secret values, or consumer `Directory.Build.props`. Use the action manifest for required fields and defaults; do not paste credentials or live config into documentation, issues or logs. The organization/consumer controls token scopes, Azure access, environment protection, rotation and secret storage; those policies are not defined here.

| Input family | Current use / boundary |
| --- | --- |
| `github-token` | Checkout, private GitHub packages/modules, pushes, releases or API access depending on action. Terraform deploy sets a masked environment token and Git credential helper; destroy and format-validate instead set a global credential URL containing the token. Docker publish sends it as the `NUGET_PAT` build argument. GitHub PR review requires `pull-requests: write`; choose permissions per consumer use. |
| Azure credentials | Azure actions accept `azure-credentials` service-principal JSON or `azure-profile` publish profile; Terraform deploy logs in with Azure CLI, destroy/format-validate export `ARM_*` variables. Supply these via consumer secrets with least-privilege access to the intended subscription/resource. Do not infer OIDC support from these actions. |
| Environment config | App Service, Function and .NET Docker actions optionally run `scripts/azure/update-config.py` on `config-file-path`. It fetches **GitHub environment variables**, lowercases names **and values**, and writes them into the consumer JSON file. This is not a secrets fetch; do not put secret material in environment variables to work around it. Review resulting files before packaging, and avoid committing generated config. |
| Terraform variables and plans | `tfvars-content` is written as `terraform.tfvars` in the consumer working directory. Deploy/destroy upload plan binary, JSON and `result.txt` as workflow artifacts for 15 days; plans may contain sensitive values. Restrict workflow/artifact access, do not copy plans to tickets, and handle local files according to consumer policy. |
| Version/build files | NuGet scripts operate on consumer `Directory.Build.props` (a `<Version>` property) and may edit `.csproj` metadata; image actions can read a consumer version file or explicit `version`. `version.txt` in this repo is used by GitHub/Terraform version-update actions when selected; it is not proof of an action-library release. |

Several steps interpolate inputs into shell commands and some configure credentials globally or in clear-text NuGet sources on the runner. Treat an action run as privileged, avoid untrusted input in privileged workflows, and inspect the action at the chosen ref before granting credentials. GitHub masking and workflow secret redaction are not a guarantee that generated artifacts, image layers, config files, plan output or runner state contain no sensitive data. Security hardening is outside this documentation-only change; raise a code/security issue for behavior changes.
