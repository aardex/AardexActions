# Safe troubleshooting entry points

1. Identify the consumer workflow run, action directory and resolved Git ref. Read its `action.yml` at that ref and the first failing step; the current README may not describe an older ref. Inspect nested `aardex/AardexActions/...@main` calls separately. Never rerun an opt-in apply/destroy/publish step just to collect logs.
2. Check inputs and job permissions **by presence and intended scope**, not by printing values. Verify expected workspace paths, branch/ref, version-file path, target Azure subscription/environment, and token access to private GitHub modules/packages. Check [configuration](configuration.md) before sharing any logs/artifacts.
3. For Terraform, distinguish init/auth failures from validate/plan failures. A failed plan can also make the `if: always()` show/upload steps fail or produce incomplete artifacts. Inspect `result.txt` and JSON only in an authorized, restricted location; confirm `apply` is false for diagnostic runs. `needs-approval` on deploy does not gate execution.
4. For .NET or Java jobs, reproduce build/test failures in the **consumer project** with the SDK/Gradle versions in the manifest. This repo has no solution to build. For Docker/Container App jobs, distinguish build/push, Trivy scan and Azure update steps; a pushed image is not proof of a completed Container App update.
5. For config injection failures, check that the chosen GitHub environment exists, the token can read its variables, and the JSON file path is correct. The helper lowercases variable names and values and does not fetch secrets. For NuGet/version failures, inspect the consumer's `Directory.Build.props` `<Version>` and the particular version script; do not edit published tags/packages as a diagnostic step.

If the issue is in an external service or a consumer-owned environment, escalate to that owner with sanitized step name, action/ref, error category and time/run link. Do not include token values, tfvars, plan artifacts, generated config, publish profiles or raw credentials. Rollback/recovery decisions for target infrastructure and releases are not specified in this repository; obtain the consumer's approved procedure before action.
