# Reviewed Terraform apply

This action applies a saved plan produced by `terraform-deploy` with `plan-storage: azure-blob`. Consumers can use it directly or select `execution-mode: reviewed-apply` on the unified `terraform-deploy` action, which delegates here at a pinned revision. The consumer is responsible for its review and authorization process. The action does not configure or enforce GitHub Environment protections.

The plan action hashes the saved binary before the count and optional human-readable summaries, then verifies the hash before conditionally creating a private Azure Blob. It reports a plan ID and SHA-256; copy both, the commit and workspace from that run. Blob metadata records repository, environment, root, workspace, Terraform version, run and attempt. No binary plan, JSON plan or captured Terraform output is uploaded as a GitHub artifact. With Blob storage enabled, `apply: true` is rejected; the legacy `plan-storage: none` immediate apply remains unchanged.

The saved-plan action authenticates to Azure with the existing `azure-credentials` service principal and optional subscription override. It verifies the checked-out commit, Terraform root, workspace and version, retrieves the plan, verifies repository/environment metadata, server-side age and the independently supplied SHA-256, then conditionally creates a single-use claim. It rechecks expiry and checksum immediately before applying that exact downloaded file. No new plan is generated. A success or failure result is recorded when possible. A claim remains after failure, cancellation or a lost runner; inspect target and state, then obtain authorization and generate a new plan rather than retrying the old one. Terraform state locking remains enabled. The supplied examples use a shared concurrency group but do not coordinate manual or cross-repository operations.

## Security tradeoff

The architecture owner accepts the administrative risk of reusing the existing CI service principal. It has `Storage Blob Data Contributor` on the plan account and may modify or delete plans and claims; storage-level immutability against it is not guaranteed. Private storage, Azure access control, independent checksum, context metadata, conditional creation and single-use claims protect the normal application path against mistakes and unauthorized substitution within that path. They do **not** protect against an attacker controlling both the privileged principal and CI workflow. Never claim the checksum or conditional writes are an independent boundary against that attacker.

Human-readable summaries can expose values Terraform does not recognize as sensitive, resource identifiers and outputs. GitHub masking is not guaranteed. Enable only when the workflow-run audience is authorized; verify the summary actually uploaded and compare the ID and SHA before accepting a review. The human section is omitted above 180000 bytes. Plans over 32 MiB are rejected. Runner termination can leave local sensitive files; protect and clean persistent runners. Lifecycle deletion is asynchronous.

The inactive [unified workflow example](../terraform-deploy/examples/persistence-alpha-plan.yml) shows the three execution modes. Replace `ACTION_COMMIT` with a reviewed commit and supply existing credentials and configuration.

## Validation

In `terraform-deploy/tests`, run `python3 -m unittest test_plan.PlanTests test_plan.LocalTerraformTests.test_real_human_plan_sensitive_and_nonsensitive test_plan_store -v`. Tests use synthetic files, an in-memory Blob model and a fake Terraform executable; the local Terraform fixture creates a plan with the built-in provider and no cloud access. The compatibility fixture contains synthetic plan bytes and metadata generated by the previous publisher at `b6bc7e2c72f868102908b454223a4157f2dd7689`. The separate `test_disposable_local_plan_and_apply` invokes a real local apply and is excluded. Also run shell syntax checks, YAML parsing and `git diff --check`. Real Azure Blob permissions, private connectivity, lifecycle cleanup and hosted workflows require nonproduction verification.
